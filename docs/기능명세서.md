# 기능 명세서

> 시스템명: 실습실 PC 통합 관제 및 원격 관리 시스템  
> 기준 코드: `backend`, `frontend`, `agent`, `common` 모듈  
> 작성 기준일: 2026-06-08

---

## 1. 문서 개요

본 문서는 현재 코드에 구현된 기능을 기준으로 백엔드, 프론트엔드, 에이전트, 공통/배포 기능을 정리한 기능 명세서이다. 시스템은 강의실 실습 PC의 상태 확인, 전원 제어, 파일 배포, 명령 실행, 보고서 생성, 알림 확인을 중앙에서 수행하기 위해 구성되었다.

---

## 2. 사용자 및 권한

| 구분 | 설명 | 주요 기능 |
| --- | --- | --- |
| 관리자 | 시스템 전체를 관리하는 사용자 | 로그인, PC 관제, 명령 발행, 파일 배포, 설정 관리, 사용자 관리, 보고서, 알림 확인 |
| 조회 사용자 | 관제 화면을 확인하는 사용자 | 대시보드 조회, 상태 확인, 제한된 화면 접근 |
| 에이전트 | 관리 대상 PC에 설치되는 백그라운드 프로그램 | 자동 등록, 하트비트 전송, 명령 수신/실행, 파일 수집/배포, 로그 기록 |

## 4. 주요 업무 흐름

### 4.1 수업 시작 전 PC 준비

1. 관리자가 로그인한다.
2. 강의실 현황에서 대상 강의실을 확인한다.
3. 오프라인 PC에 Wake-on-LAN 명령을 발행한다.
4. 에이전트가 온라인 상태를 하트비트로 보고한다.
5. 관리자는 강의실 온라인 비율과 교사 PC 상태를 확인한다.

### 4.2 수업 종료 후 PC 정리

1. 관리자가 대상 강의실 또는 PC 목록을 선택한다.
2. 종료 명령을 발행한다.
3. 에이전트가 OS 종료 명령을 실행한다.
4. 서버는 하트비트 미수신 또는 종료 알림으로 오프라인 상태를 반영한다.
5. 관리자는 꺼지지 않은 PC만 다시 확인하거나 재명령한다.

### 4.3 대용량 파일 배포

1. 관리자가 배포할 파일을 선택한다.
2. 프론트엔드는 서버로 청크 업로드를 수행한다.
3. 백엔드는 파일을 조립하고 배포 Job을 생성한다.
4. 서버는 대상 PC를 웨이브 단위로 나누어 배포한다.
5. 일부 에이전트는 피어 캐시 서버를 열어 다른 에이전트의 다운로드 후보가 된다.
6. 성공/실패 상태와 이벤트를 프론트에서 확인한다.

### 4.4 에이전트 자동 등록

1. 에이전트 MSI를 대상 PC에 설치한다.
2. 설치 후 자동 시작 작업이 등록된다.
3. 에이전트가 서버 URL과 설치 키를 읽는다.
4. 토큰이 없으면 등록 API를 호출한다.
5. 서버가 에이전트 토큰을 발급한다.
6. 이후 에이전트는 토큰으로 하트비트와 명령 API를 호출한다.

## 5. 비기능 요구사항 반영

| 구분 | 내용 |
| --- | --- |
| 안정성 | 에이전트 자동 시작, 단일 인스턴스, 명령 결과 재보고 저장소를 통해 현장 PC의 불안정한 실행 상태를 보완한다. |
| 확장성 | 웨이브 배포와 피어 캐시 구조로 다수 PC 배포 시 서버 부하를 줄인다. |

| 호환성 | 에이전트는 jlink 번들 JRE를 포함하여 PC별 Java 설치 상태에 의존하지 않는다. |
