# 이미지 업데이트 & 부팅 검증 체크리스트

이 문서는 강의실/PC 이미지(골든 이미지) 수준에서 업데이트를 배포할 때 운영자가 따라야 할 최소 절차를 정리합니다.

요약 원칙
- 에이전트 로컬 상태는 스냅샷 복원 정책에 영향을 받음. 로컬에만 기록된 토큰/마커는 재부팅 시 사라질 수 있음.
- 신뢰 가능한 영속성은 (A) 골든 이미지 갱신, (B) 별도 영구 파티션/네트워크 스토리지, 또는 (C) 서버 기반 재발급 흐름을 통해 보장해야 함.
- 에이전트 업데이트는 기본적으로 관리자가 명시적으로 선택한 PC에만 배포합니다. 하트비트 자동 캐치업은 기본 비활성화이며 별도의 운영 승인이 있을 때만 사용합니다.

사전 준비
1. 운영관리자는 배포할 ScriptArtifact(또는 업로드)를 서버에 업로드하고 FileDistributionJob을 생성합니다.
2. Job의 `targetVersion`이 새 이미지/에이전트 버전을 가리키는지 확인합니다.
3. `app.file-distribution.auto-catchup-on-heartbeat=false`인지 확인합니다. 전체 버전 자동 정렬이 필요한 별도 작업에서만 일시적으로 활성화합니다.

이미지 배포 절차
1. 골든 이미지(또는 이미지 빌드)를 생성하고 테스트 이미지로 몇 대에서 검증합니다.
2. 골든 이미지를 프로비저닝 시스템(이미지 배포 시스템, USB, PXE 등)을 통해 강의실에 반영합니다.
3. 서버에 FileDistribution job(또는 수동 AGENT_UPDATE 명령)을 생성하여 해당 그룹 또는 에이전트에 대상 버전을 설정합니다.

부팅 후 검증 (운영자 체크)
1. 대시보드에서 대상 PC의 `agentVersion`을 확인합니다 (대시보드 또는 `/api` 조회 가능).
2. 선택한 PC만 배포 Job 대상에 포함됐는지 최근 배포 작업의 대상 수와 에이전트 상태를 확인합니다.
3. 에이전트 버전이 기대치와 다르면 해당 PC만 다시 선택해 배포합니다.

롤백/재현성 처리
- 스냅샷으로 인해 이전 시점으로 돌아간 경우, 자동 캐치업 대신 해당 PC를 명시적으로 선택해 다시 배포합니다.
- 수동 개입: 대상 PC에 원격 접속하여 수동으로 업데이트를 적용하거나, 그룹 대상 파일배포 Job을 다시 실행하세요.

검증 명령(예시)
- 대시보드에서 빠르게 확인: 관리자 UI에서 PC 리스트의 `agentVersion` 확인.
- 직접 DB (관리용 환경에서만):
```sql
SELECT mac_address, ip_address, agent_version, last_seen, status
FROM pc_master
WHERE mac_address = '<MAC>';
```

운영 팁
- 에이전트가 부팅 후 곧바로 네트워크에 연결되지 않으면, 캐치업이 지연될 수 있음. 부팅 시 네트워크 의존성(프록시, VLAN, DNS)을 점검하세요.
- 키체인/로컬 토큰에 의존하지 마십시오. 스냅샷 복원 환경에서는 서버 기반 발급 흐름(짧은 만료 토큰 + 프로비저닝 토큰)을 사용하세요.
- 자동 롤백 임계치, 캔버이 비율, wave size는 파일 분배 설정에서 조정합니다(작은 파이프라인으로 안전하게 확장).

문제 발생 시 체크리스트
1. PC가 `OFFLINE`으로 계속 표시된다 → 네트워크/방화벽/프록시 확인.
2. 서버가 `targetVersion`을 생성했으나 agent가 업데이트하지 않음 → 해당 PC를 수동으로 대상 그룹에 다시 추가 후 재시도.
3. 반복적인 롤백(재부팅 시 항상 이전 버전으로 돌아감) → 이미지 배포 절차(골든 이미지 반영)를 재검증.

참고: 이 체크리스트는 시스템의 자동 캐치업 기능을 전제로 합니다. 로컬 퍼시스턴스(예: 영구 파티션 또는 중앙 스토리지)를 사용하면 일부 절차를 단축할 수 있습니다.

클론(디스크 복사)으로 다른 PC에 이미지를 복사한 후 수동으로 이전 PC의 식별자(예: PC명, IP, MAC)를 복구해야 하는 경우
- 요약: 디스크 복사 환경에서는 하드웨어(특히 NIC의 MAC 주소)가 바뀌기 때문에 서버의 에이전트 토큰/식별자와 불일치가 발생할 수 있습니다. 이 시스템은 보안을 위해 에이전트 토큰에 연결된 MAC을 비교하므로, 복제된 이미지를 새 PC에 적용한 뒤에는 `config.json`에 수동 오버라이드를 넣어 이전 식별자를 재사용해야 정상 동작합니다.

- 조치 방법 (운영자):
	1. 복사된 머신에서 에이전트를 정지합니다 (서비스/프로세스 중지).
	2. 복사된 `config.json` 위치를 확인합니다 (기본: `%APPDATA%\\PCAgent\\config.json` 또는 `~/.pcagent/config.json`).
	3. `config.json`을 열어 아래 필드가 있는지 확인하고, 없으면 추가합니다:

```json
{
	"overrideMacAddress": "AA:BB:CC:DD:EE:FF",
	"overrideHostname": "원래-PC-이름",
	"overrideIpAddress": "192.168.1.100"
}
```

	- `overrideMacAddress`: 서버에 등록된 원래 기기의 MAC 주소(콜론 구분, 대문자 권장)
	- `overrideHostname`: 원래 PC의 호스트명
	- `overrideIpAddress`: (선택) 원래에 사용하던 IP. DHCP 환경이면 비워둘 수 있음.

	4. `config.json`을 저장한 뒤 에이전트를 다시 시작합니다. 에이전트는 재등록/하트비트 시 오버라이드 값을 사용하므로 서버 토큰과 일치하면 정상적으로 인증됩니다.

- 주의사항/보안
	- 이 방법은 운영자가 신뢰하는 환경에서만 사용하세요. 누구나 임의 토큰을 다른 장비에서 사용하면 보안 위험이 있어, 오직 골든 이미지 복사/프로비저닝 상황에서 관리자가 통제하는 경우에만 허용해야 합니다.
	- 오버라이드 값 사용 시, 같은 `agentToken`을 여러 장비에 복제하여 동시에 사용하면 서버에서 세션 충돌/명령 재큐잉이 발생할 수 있습니다. 가능한 한 이미지 복사 후 한 장비씩 프로비저닝하고 검증하세요.
