## 1. 테스트 개요

### 1.1 목적
시스템의 모든 기능이 기능명세서에 따라 정상 동작하는지 검증하고, 보안·성능·안정성을 확인한다.

### 1.2 테스트 범위

| 영역 | 대상 | 범위 |
|------|------|------|
| 백엔드 API | 17개 컨트롤러, 100+ 엔드포인트 | 기능/보안/에러 처리 |
| 프론트엔드 UI | 로그인 + 대시보드 5탭 + 위젯 | 기능/UX/반응성 |
| 에이전트 | 하트비트, 명령 실행, WOL | 기능/안정성/복구 |
| 통합 | 에이전트↔서버↔프론트 E2E | 시나리오 기반 |
| 보안 | 인증/인가/인젝션 | OWASP Top 10 |
| 성능 | 830대 동시 하트비트 | 부하/응답시간 |

### 1.3 테스트 환경

| 환경 | 구성 |
|------|------|
| **개발** | 로컬 PC, SQLite, http://localhost:8888 |
| **스테이징** | Docker Compose, Nginx, HTTPS |
| **에이전트 테스트** | Windows 10/11 VM (최소 3대) |

### 1.4 테스트 도구

| 도구 | 용도 |
|------|------|
| JUnit 5 | 백엔드 단위·통합 테스트 |

## 2. 테스트 전략

### 2.1 테스트 레벨

```
Level 4: E2E 테스트 (시나리오 기반)
  └── 에이전트 설치 → 등록 → 하트비트 → 명령 실행 → 결과 확인
Level 3: 통합 테스트 (API + DB)
  └── 컨트롤러 → 서비스 → 레포지토리 → SQLite
Level 2: 컴포넌트 테스트 (서비스 단위)
  └── 서비스 로직, 캐시, 스케줄러
Level 1: 단위 테스트 (클래스/메서드)
  └── DTO 변환, 유틸리티, 검증 로직
```

### 2.2 테스트 유형별 목표 커버리지

| 유형 | 목표 | 현재 |
|------|------|------|

| 통합 테스트 | 핵심 API 100% | 부분 구현 |
| UI 테스트 | 주요 화면 흐름 | 부분 구현 |

## 7. 결함 관리

### 7.1 결함 심각도

| 등급 | 정의 | 대응 |
|------|------|------|
| Critical | 시스템 장애, 데이터 손실, 보안 취약점 | 즉시 수정 |
| Major | 핵심 기능 불가, 대안 없음 | 24시간 내 수정 |
| Minor | 기능 불완전, 대안 있음 | 다음 릴리스 수정 |
| Cosmetic | UI 미미한 결함, 오타 | 편의 수정 |

### 7.2 테스트 완료 기준

- Critical/Major 결함 0건
- Minor 결함 해결률 80% 이상
- 핵심 시나리오 5건 전체 통과
- 보안 테스트 P1 항목 전체 통과
